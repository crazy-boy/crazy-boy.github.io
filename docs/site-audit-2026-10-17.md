# 博客整体审查与优化建议

审查日期：2026-10-17。范围：本地源码、全量构建、内容元数据统计、主要页面与文章生成 HTML、站内资源路径、书籍导航。线上首页可获取，但部分文章无法通过本次抓取工具访问；以下结论以本地构建为准，不据此判断线上服务故障。未完成浏览器视觉验收、真实网络测速或逐篇技术事实核查。

## 现状

- 326 篇博文，时间跨度为 2016—2026 年；另有 79 个书籍页面。
- 83 个分类，288 个标签。其中 50 个分类、242 个标签仅关联一篇文章。
- 326 篇博文均未设置 `summary`，列表依赖截取正文。
- 主题已有文章桌面目录、代码复制、搜索范围筛选、按时间阅读和书籍上下章导航。这些基础值得保留。
- `npm run build` 成功，生成 1284 个文件；`npm run check:books` 通过 79 页导航检查。
- 生成文件总大小约 105.7 MB，不等于单页传输大小；含下载 EXE、相册和全站资源。

## 第一优先级：修复影响准确展示的问题

### 1. 错误日期让老文章显示成新文章

`source/_posts/系统设计及优化/架构/记一次高并发迭代之路.md` 中日期为 `2020--03-15 11:31:24`。Hexo 缓存和生成页实际采用了 `2026-10-16`。该文章有 `top: 999`，置顶本身是明确配置，但错误日期还会影响时间线、最新文章和 Feed 等按日期排序的入口。

建议：修正该日期，发布前校验日期合法性、重复 permalink/abbrlink；明确设置 `timezone: Asia/Shanghai`，减少不同构建环境对时间解释的差异。不要为了让文章显得新而批量刷新发布日期。

### 2. Mermaid 图表没有被渲染

13 篇博文包含 Mermaid 代码块，包括智能体、死锁、银行家算法、Shor、Grover 和 Mermaid 教程。当前构建保留流程图代码，未生成 SVG；页面也没有 Mermaid 渲染脚本。

建议：优先为包含 Mermaid 的文章提供图表渲染。可选构建时生成 SVG，或按需加载浏览器渲染器；验证失败时保留可读源码，不让一张图阻断整页。无需给每页加载图表库。

公式也需单列抽查：例如 Diffie-Hellman、Shor 等文章有公式写法，但未加载 MathJax；当前 MathJax 由 frontmatter 手动开启。不要仅检查主题中 `enable: true` 就认为所有文章公式都能展示。

### 3. 文章 SEO 描述计算后没有使用

`themes/itsneko/layout/_partial/head.ejs` 第 42 行开始计算文章级 `description`，但第 70 行输出的是 `config.description`。抽查范围内 410 个使用主题的页面使用同一句站点描述。

常规文章页面还没有 canonical、Open Graph 或 BlogPosting 结构化信息。

建议：先接通文章摘要，再补 canonical 和分享元信息；结构化信息使用真实的作者、发布日期、更新时间，不承诺排名提升。Google 对摘要和文章结构化数据有对应说明：

- https://developers.google.com/search/docs/appearance/snippet
- https://developers.google.com/search/docs/appearance/structured-data/article

### 4. 手机阅读长文缺少目录入口

`themes/itsneko/source/css/post-toc.css` 在宽度不超过 992px 时隐藏目录；模板中的目录按钮也只显示在桌面。`head.ejs` 同时设置了 `user-scalable=no`。

建议：手机端增加折叠目录或抽屉目录，允许手势缩放。现有桌面目录与正文样式可以保留。用窄屏验证代码横向滚动、表格、目录跳转与暗色模式。

## 第二优先级：让已有文章更容易被找到和连续阅读

### 5. 分类过细，标签没有形成稳定主题

分类有 PHP/php，标签有 PHP/php、MySQL/mysql、JQuery/Jquery 的分裂。单篇分类占 50/83，单篇标签占 242/288。

建议：先确定少量稳定的主分类，例如后端开发、数据库与缓存、架构与性能、算法与基础、安全与密码学、运维与工具、工程实践、随笔；这是待讨论的导航方案，不是需要立即批量迁移的最终分类表。

将细粒度概念保留为标签，优先合并大小写和同义项。分类迁移会改变分类 URL，应保留旧入口或配置重定向。文章现有 `/posts/:abbrlink.html` 应继续稳定。

### 6. 增加专题入口和有顺序的阅读路径

当前入口主要是最新文章、分类、标签和时间线，文章结尾按时间展示上一篇/下一篇。正文之间缺少有意识的主题互链，容易读完一篇就结束。

建议：优先整理已有内容最丰富的 PHP、MySQL、架构实践、安全与密码学专题。每个专题提供问题导向简介、入门顺序、进阶文章和真实案例。文章末尾增加 3—5 篇有理由的相关阅读，可保留时间上下篇。

首页增加“从这里开始”“实践复盘”“专题阅读”的精选入口，让新读者快速理解作者擅长什么。无需先换框架或大幅重做视觉设计。

### 7. 区分速查笔记、实践复盘和系统教程

按 Markdown 正文去空白后的长度筛查，有 66 篇不足 500 字符；这只是复核候选，不是质量评分。

具体例子：

- “心跳包机制”只有一句用途介绍。
- “目标管理”接近提纲。
- 两篇“Excel使用小技巧”内容高度重合，分别位于 Office 和 Windows/Excel。
- “centos7安装mysql5.0版本教程”的正文下载包却是 MySQL 5.7.27，标题与内容版本不一致。

建议：短小但有用的命令保留为速查笔记；提纲型内容补完或合并。重复文章合并时保留旧 URL 的跳转。旧教程标注适用版本、环境和核验时间，避免读者当作当前通用方案。

作者的工作经验是有区分度的内容。像高并发复盘中的业务规模、带宽、压测失败率、慢查询定位，应补成“现象—证据—判断—方案—结果—代价”的完整案例。

较宏观的综述文章则适合减少没有来源的断言和抽象口号。例如 AI 文章中的具体行业数量、比例应补充来源、统计时间和口径；本次仅识别到引用缺口，并未验证这些数字对错。

## 第三优先级：降低加载与维护成本

### 8. 搜索索引需要控制体积

`public/search.xml` 为 5,146,421 字节，约 5.1 MB（未压缩文件大小）。搜索脚本已经按首次输入加载、加了 150ms 防抖和最多 60 条展示，这些机制是有效基础。

但首次搜索仍需下载完整 XML，在主线程逐条解析正文，后续每次搜索也遍历全文。

建议：先生成轻量 JSON，剥离无关 HTML、复用预处理后的检索文本；按文章/书籍分片，必要时用 Worker 搜索。是否需要第三方托管搜索，应等本地优化和实测后决定。上线后核实实际压缩传输量与首次搜索耗时。

### 9. 图片与公共依赖可减负

首页 16 张 img 均没有原生懒加载属性。头像原图约 3.2 MB，雨天照片约 7.3 MB，相册多张照片在 1—3 MB；是否首屏加载应结合具体页面判断，不把全站大文件都算进首页。

建议：为头像生成合适尺寸，为照片提供缩略图与 WebP/AVIF；屏外图片懒加载并设置尺寸，首屏主图保持及时加载。原图可继续供查看。参考：https://web.dev/articles/browser-level-image-lazy-loading

全站同时加载本地 Font Awesome 5 与 CDN Font Awesome 4，部分视觉插件在不使用它们的页面也加载。先核对图标兼容性，再合并图标来源、按页面加载 Masonry、AOS、图片灯箱等，不宜直接删除造成布局或行为回归。

### 10. 清理模板遗留项，并建立通用发布校验

本次内容页及核心页扫描发现 3 个缺失的共享装饰图片路径；其中 `shengdanren4.png` 被 325 个文章页引用。返回顶部链接写成 `href="javascript(0)"`，它会被解析为相对路径；当前点击处理可能掩盖问题，应改成语义正确的 button 或锚点。

百度推送脚本在 head 和公共 partial 中重复插入。可集中到一个开关控制的位置。模板还保留较多无效注释与内联样式，可在触及对应模块时逐步整理。

CI 已经有干净构建和书籍检查，建议扩充全站检查：

- 日期有效性，重复路由，工具元数据与下载文件哈希。
- 内容页、导航和静态资源的站内链接；另外检查 CSS 背景图与 srcset。
- Mermaid/公式示例、手机目录、搜索成功与失败重试。
- title/description/canonical 等元信息；必要时加入有代表性的浏览器回归检查。

不要让检查只验证“构建命令成功”；当前缺失图片、图表未渲染和错误日期都未阻止构建。

## 推荐实施顺序

1. 修复错误日期、缺失资源、返回顶部链接和重复推送；补 Mermaid/公式验证。
2. 接通文章摘要与元信息，增加手机目录和缩放支持。
3. 合并标签别名，整理 3—4 个重点专题与精选文章。
4. 优化图片、搜索和按需依赖加载，用真实浏览器与线上网络数据验证收益。
5. 逐批维护旧文章及重复内容，不一次性重写全部历史文章。

本次只完成审查与报告，没有修改文章、主题或部署配置，也没有发布站点。
