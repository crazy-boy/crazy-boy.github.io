“不要自己发明密码”是安全开发的第一条铁律，但仅仅是“使用库”还不够。如果使用方式错误，即使是最强大的密码学库，也可能形同虚设。本章节将带你掌握正确使用密码学库的核心原则，并通过具体示例展示安全实践。

### 选择正确的库

在开始之前，你需要选择一个可靠的密码学库。以下是一些被广泛认可的选择：

- **libsodium**：现代、易用、跨平台，提供了高层次的 API，默认安全。适合大多数应用。
- **OpenSSL**：功能最全，但 API 复杂，容易误用。仅建议在需要兼容旧系统或特定功能时使用，且需谨慎。
- **语言原生库**：
    - Python：`cryptography`（第三方，推荐）、`hashlib`、`secrets`（标准库）。
    - Go：`crypto` 标准包（如 `crypto/aes`、`crypto/rand`、`crypto/ed25519`）。
    - Java：`java.security` 标准包 + Bouncy Castle（补充）。
- **专用库**：如 `tink`（Google 出品，简化常见任务）、`age`（文件加密）等。

选择标准：
- **活跃维护**：库应定期更新，修复漏洞。
- **文档完善**：有清晰的 API 说明和安全指南。
- **安全审计**：经过独立安全审计更佳。
- **高层封装**：优先选择提供“安全默认”的库，如 libsodium 的 `crypto_secretbox` 直接完成认证加密。

### 正确使用库的通用原则

1. **使用最新稳定版本**：旧版本可能存在已知漏洞。
2. **遵循库的安全指南**：每个库都有官方推荐的用法，请务必阅读。
3. **避免使用“低级”原语**：优先选择高层 API（如认证加密、密钥封装），而不是直接调用 AES 或 RSA 原始操作。
4. **不要硬编码密钥**：密钥应从安全存储（如密钥管理系统、环境变量）中读取，绝不可写死在代码中。
5. **正确处理错误**：检查每个函数的返回值，失败时要安全退出（如清除敏感数据后抛出异常）。
6. **使用随机数生成器**：所有随机值（密钥、IV、盐）必须使用库提供的安全随机数生成器，不要自己造。

### 常见错误与规避

1. **使用 ECB 模式**：永远不要用！ECB 模式会暴露数据模式。
2. **固定 IV**：IV 必须每次随机生成（除非使用计数器模式且保证不重复）。
3. **忽略认证标签**：如果只加密不认证，攻击者可能篡改密文。务必使用认证加密（如 GCM、ChaCha20-Poly1305）。
4. **错误处理不当**：解密失败时，不要返回具体错误信息（以免被利用），应统一返回“解密失败”。
5. **密钥泄露**：密钥应存储在专用密钥管理服务中，不在代码中硬编码，不在日志中打印。
6. **内存清理**：对于敏感数据（如密钥、明文），使用后应立即覆盖（如 Java 的 `Arrays.fill`，Go 的 `zero`）。

### 小结

正确使用密码学库是一门严谨的工程实践。它要求我们：
- 选择成熟的库，并保持更新。
- 使用高层 API，避免直接操作原语。
- 遵守安全随机数、认证加密、正确密钥管理等铁律。
- 熟悉所选语言的官方安全指南。

当你在代码中集成加密时，请始终问自己：这个实现是否通过了安全审计？是否遵循了库的最佳实践？如果答案不确定，不妨寻求安全专家的帮助。安全开发不是“能用就行”，而是“在所有可能攻击下依然安全”。唯有如此，你的系统才能在真实世界中经得起考验。
